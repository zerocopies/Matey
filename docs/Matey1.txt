    *   **Step 1: Naming:** A text input field to name the tab (e.g., "Project Alpha", "Client Briefs"). This sets the UI string for the tab label.
    *   **Step 2: Template Selection:** A selection interface presenting the four defined "Out of the Box" templates. Each template must have a title, icon, and brief description.

### 2. Supported "Out of the Box" Customization Templates
Implement the logic and UI rendering for the following four templates:

*   **Template A: The "AI Assistant" (Dynamic Chat)**
    *   **Function:** Dedicated chat interface distinct from the ambient Recap feed.
    *   **Configuration:** Wizard prompts for: 
        1. **Role Definition** (e.g., "Expert Researcher", "Python Tutor").
        2. **Topic Focus** (e.g., "Market Trends", "API Refactoring").
    *   **Backend:** Initialize this view's local LLM instance with a custom system prompt derived from these configurations: * "You are Matey's AI Assistant acting as an `{Role}`. Focus your responses strictly on `{Topic}`. Do not use the Knowledge Bank unless explicitly asked."*

*   **Template B: The "Knowledge Filter" (Dynamic RAG Feed)**
    *   **Function:** A filtered feed view, similar to Recap, but scoped exclusively to user-defined criteria.
    *   **Configuration:** Wizard prompts for:
        1. **Tags** (e.g., `#ProjectA`, `#ClientX`).
        2. **Keywords** (e.g., "Budget", "Deadline").
    *   **Backend:** When active, this view must override the global personalization profile and execute a local RAG query matching *only* the configured `{Tags}` and `{Keywords}` against the Knowledge Bank and incoming hooks.

*   **Template C: The "Task & Priority Center" (Actionable View)**
    *   **Function:** An actionable Kanban-style or list view of tasks and priorities extracted from notes.
    *   **Configuration:** No specific parameters required beyond selection; the template defaults to scanning all notes.
    *   **Backend:** Implement a dedicated parser to scan the Knowledge Bank (all `##` and `**` notes) for markdown tasks `[ ]` and priority flags `!!`.
    *   **Display:** Render these items in a clean, borderless list view, grouped by status (Pending/Done) or original note context.

*   **Template D: The "Connect & Track" (External Integration View)**
    *   **Function:** A view displaying data fetched from external services via webhooks.
    *   **Configuration:** Wizard prompts for:
        1. **Service Name** (e.g., "GitHub", "Trello", "Email").
        2. **Webhook URL** (Input field for secure endpoint URL).
    *   **Backend:** Utilize the `//` silent automation engine to periodically ping the configured `{Webhook URL}`.
    *   **Display:** Render the returned external data payload in a structured, read-only dashboard format within the tab.

### 3. Technical Implementation & State Management
*   **URL Scheme/Deep Linking:** Structure the Custom Tab configuration as an internal deep link state blob stored securely on the device (e.g., `matey://custom-tab?config={base64_encoded_json_config}`).
*   **Internal Router:** Modify the application's main navigation router to detect the activation of the Custom Tab and execute the corresponding rendering logic based on the stored configuration blob.
